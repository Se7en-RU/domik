# Измерения дома

`PLAN.md` — принятый владельцем план работы. `raw/` — неизменяемые оригиналы RoomPlan; мебель в этих файлах может присутствовать, но обработка читает только архитектурные поля. `manual/control.json` — три ручных контроля с привязками к стабильным ID существующей модели. Значения в метрах.

## Повторить проверку

```sh
npm run measurements:audit
npm run measurements:apply
npm test
npm run typecheck
npm run build
```

Первая команда рекурсивно обрабатывает все JSON в `raw/`, сохраняет нормализованную архитектуру в игнорируемом `work/roomplan/normalized/` и обновляет `reports/audit.json`, `reports/REVIEW.md`, `reports/overlay.html`. Исходные файлы и `lib/house.json` не меняются. Неизвестные форматы и некорректные матрицы попадают в отчёт как REVIEW REQUIRED.

Вторая команда создаёт этот же отчёт **до** изменения модели. Она применяет только сопоставленные ручные контроли с явно заданными связанными правками: обе грани поперечных стен, прилегающие полигоны и перегородку/верхний марш/пол кладовой. Проверки выполняются на копии спецификации до записи. Неожиданная топология, рассогласование ручных контролей или параллельное редактирование файла останавливают запись. `before-apply.json` сохраняет исходные предложения; `applied.json` — применённые значения и результат проверки. Повторный запуск после применения не меняет геометрию. Новые типы ручных контролей требуют явного правила связанного редактирования, неизвестная цель не применяется.

RoomPlan не порождает автоматических независимых сдвигов стен. Его расхождения используются как доказательства и кандидаты: `IGNORE` для подтверждённой привязки с отклонением менее 1 см, остальные — `REVIEW REQUIRED`, пока нет согласованного решения соседних комнат, проёмов и этажей. Порог более 5 см обозначает сильного кандидата на анализ, а не разрешение менять модель.

## Координаты и сопоставление

Матрицы — column-major. Нормализатор использует полноценную обратную матрицу; прежняя ручная формула неверно обращала перенос при повороте. Пол RoomPlan лежит в локальной XY-плоскости, его Z — нормаль. Новый нормализатор сохраняет все `polygonCorners` и строит горизонтальные X/Z с вертикальной Y. Общее преобразование `referenceOriginTransform` применяется к полу и поверхностям одинаково и сокращается в относительной геометрии; оно не считается доказательством общей регистрации разных сеансов. Исходное преобразование сохраняется в нормализованном файле.

Положение комнаты выбирается по стенам, форме, длинам, уступам и расположению проёмов среди обоих этажей, включая объединённую кухню/гостиную и коридор/лестничный проём. Имена файлов, `sections`, мебель и UUID не определяют выбор. UUID используются только для трассировки и `parentIdentifier` внутри скана. Масштаб всегда 1, отражение запрещено. Альтернативные регистрации сохраняются; симметричные прямоугольники без достаточных проёмов могут остаться неоднозначными. Область, включающая два этажа, не получает высоту обычной комнаты.

Размеры относятся к поверхности/грани комнаты, не автоматически ко всей оси стены. Оконные откосы и частичные поверхности учитываются отдельно от полных граней. Окна и двери сопоставляются через родительскую стену; расхождение категории сохраняется для проверки. Новый проём автоматически не создаётся. Высоты вычисляются относительно нормализованного пола, однако связь вертикальных отметок между независимыми сканами требует контрольного обмера.

## Доказательства и точность

Один скан даёт не более одного независимого голоса для одного параметра. Геометрический отпечаток исключает одинаковые копии даже с заменёнными UUID; это защита от точных дублей, а не доказательство независимости почти одинаковых экспортов одного сеанса. Медиана и MAD выделяют явные выбросы, все значения сохраняются в отчёте. Неоднозначная привязка не подтверждает другое измерение. Согласованность нескольких сканов одного прибора не исключает систематическую погрешность.

`confidence` сохранён как уверенность RoomPlan в **классификации**, не как точность в сантиметрах. Для большей точности необходимы повторные съёмки одной и той же грани и независимые ручные расстояния; имеющиеся три ручных контроля толщин не позволяют вычислять единый коэффициент масштаба для всего дома.

Локальное сопоставление торца 13 см относится к `F1-W13-DIVIDER`: в `лестница.json` поверхность `4904EAAE-6E23-4435-A505-5F50A51D89C8` имеет длину 0,12991391 м и соединяет сторону перегородки длиной 2,663 м с участком 0,943 м. Из-за наклона торца его проекция отличается от длины; значение толщины берётся из ручного замера 0,13 м. Глобальная регистрация всего скана лестницы остаётся REVIEW REQUIRED.

Контрольные значения защищены проверкой при сборке. Базовые высоты RoomPlan 3,03 / 3,045 / 2,927 м применены; высота ворот 2,70 м сохранена, потому что отдельной поверхности ворот нет. Перекрытие, скосы, глубина площадки, отметка гаража и постоянство толщин вдоль всей оси остаются допущениями. F2-WIN04 требует отдельного review из-за конфликтующих высот. Для внешних контуров и спорных высот нужны дополнительные независимые замеры.

Оригиналы `raw/` и отчёты исключены из форматирования, чтобы `npm run format` не переписывал измерения. Публикация сайта содержит только производную модель и планы из просмотрщика; сканы и отчёт туда не копируются.

## Review гаража

Решения владельца записаны в `manual/garage-review.json` и `manual/wall-continuity-review.json`, а при `measurements:audit` включаются в общий отчёт. Приняты сканированные ширина, обе боковые длины, ширина/положение ворот и выступ стены. Контур GARAGE-W05 сохранён по скану, его генерируемая грань сдвинута на 57 мм вправо до F1-W08 и снабжена скрытым соединительным участком. Высота ворот и отметка пола остаются отдельными допущениями. Геометрия сохраняет восьмиугольный контур и разницу передних углов около 3 см.
